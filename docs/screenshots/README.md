# Screenshots

The public README embeds the files in this folder:

| File | Shows |
|---|---|
| `board.png` | Reference board (empty board with the drop hint and board bar) |
| `brush-library.png` | Drawing workspace with the brush library, colour and layers |
| `pose3d.png` | Pose3D with the two-figure rig, camera/lighting panels and guides |
| `new-canvas.png` | New canvas dialog with presets, size, name and background |
| `settings-general.png` | Settings → General with the selection inspector |
| `export.png` | Export dialog with scope, formats, scale, DPI and margins |

## Rules

1. **Only use artwork the project is allowed to publish.** Do not publish
   screenshots that contain third-party images of unknown origin — this
   includes live Pinterest/ArtStation feeds. Use a local fixture or your own
   artwork instead.
2. **No personal data.** Use a dedicated profile and check that no project names,
   file paths, email addresses, usernames or notification popups are visible.
3. **Consistent setup.** Default dark theme, English interface, 16:9 content
   area at 1600 px wide or larger. Do not upscale.
4. **Optimise the files.** PNG, ideally under 1.5 MB each.
5. **Keep the names above** so the README links keep working.

## How to capture

These shots were taken manually from the running application with a dedicated
profile. If you replace them, keep the same names and check for private data
first.

`scripts/capture-docs.js` can generate an isolated demo profile with synthetic
content for reproducible captures (`node scripts/capture-docs.js`). It is a
helper, not a requirement; screenshots taken from your own artwork are
preferred.

Pose3D also has a recorded video for the product page; it is kept outside the
repository as a release asset.

Screenshots are documentation, not evidence of a test result. Do not add
captions that claim features the app does not have.
